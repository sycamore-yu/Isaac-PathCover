## 2. 故障复现与归因

先固定初版 Medium 的已发布 CmdTraj，再逐项替换执行逻辑。回放恢复原物理状态、电机状态和 50 Hz 求解相位。参考只使用当时已经发布的命令。

回放窗口为原仿真时间 4.28–6.99 s，共 271 个控制步、136 次求解。重建的位置、速度、加速度、加加速度、偏航和偏航角速度均与原记录一致。

| 固定轨迹回放 | 最大误差 / m | 均方根误差 / m | 碰撞 | 越界 | 分配饱和步数 | 力矩反向步数 |
|---|---:|---:|---|---|---:|---:|
| 原控制配置 | 2.980631 | 1.585885 | 是，6.1075 s | 是 | 231 | 133 |
| 仅修复旋翼分配 | 2.482772 | 1.609553 | 否 | 是 | 226 | 0 |
| 再修复角速度反馈 | 0.211351 | 0.122928 | 否 | 否 | 78 | 0 |
| 再调整输入成本 | 0.203088 | 0.103455 | 否 | 否 | 3 | 0 |

原配置复现了初版的碰撞时刻和最大误差。修改执行层后，同一命令不再导致碰撞或越界。角速度反馈修复带来主要跟踪改善。输入成本调整进一步减少分配饱和。

4 组回放中，每次最后一个二次规划（QP）均返回成功状态，并满足原求解容差。已保存的残差记录不支持“求解器未收敛导致本次故障”的假设。

### 旋翼分配

旧逻辑独立裁剪 4 个旋翼推力。在原故障样本中，请求滚转力矩为 -0.052565 N·m，分配后却变为 +0.050682 N·m。

新逻辑先统一缩放差动推力，再将总推力移入可行区间。这样保留三轴力矩方向，并满足每旋翼 0–8.5 N 的物理限制。它没有改变旋翼位置、推力系数或电机响应。

### 角速度反馈

旧内环只有比例反馈，增益为 8 s⁻¹。10D 预测模型直接使用期望角速度，实际内环响应却明显滞后。

新内环使用角速度比例反馈和实测角加速度阻尼。自然频率为 40 rad/s，阻尼比为 0.9。根据原电机时间常数 0.033 s，比例增益为 52.8 s⁻¹，阻尼系数为 1.376。导数项作用于实测角速度，避免参考跳变造成导数冲击。

电机滞后仍只由实际执行系统处理，没有加入 MPC 预测状态。

### 输入成本

总推力误差权重从 0.015 调整为 1.0。原成本对接近零推力的惩罚过小，使大角速度请求与低推力同时出现。

角速度输入成本改为惩罚角速度幅值，不再以较大的平坦性前馈角速度为惩罚中心。未来位置、速度和姿态仍是跟踪目标。未改变 10D 模型、SQP、ADMM 或 nvmath 求解代码。

## 3. 规划端仍有的问题

| 规划返回状态 | NMPC Medium | NMPC Dense |
|---|---:|---:|
| REPLAN_OVERTIME | 52 | 63 |
| EXP_OPT_FAILED | 1 | 0 |
| BACKUP_CORRIDOR_FAILED | 0 | 1 |
| ON_BACKUP_WAIT_FOR_REST | 0 | 3 |
| 合计失败 | 53 | 67 |

这两次 NMPC 的失败请求主要来自原重规划时间判断。Ideal 基线也有超时、优化失败和备用等待。这些问题影响等待和重规划过程，但未阻止本次 4 个对照记录到达。

在这两个场景中，初版飞行失败的直接原因来自控制执行层。固定轨迹回放支持这一判断。现有证据不能把所有规划失败都归为 A* 或 RISP 的几何搜索问题，也不能证明规划器在其他场景均可靠。

规划使用墙钟定时器，执行开销和传感器状态会影响请求序列。两种模式的轨迹与规划次数不会逐次相同。不能仅根据本表的失败次数或飞行时长，判断某控制器改善了规划算法。

## 4. 必要验证与求解耗时

执行机构回归测试为 **9 passed，1 deselected**。测试覆盖原故障样本、可行分配不变、三轴力矩统一缩放、实测角加速度反馈和重置。未运行无关的完整测试集。

最终代码通过 5 s 扰动悬停检查。初始位置偏移为 `[0.1,-0.1,0.05] m`，滚转为 0.05 rad。末态位置误差为 **1.34 mm**，速度为 **0.00606 m/s**。分配推力为 1.543681–2.008437 N，满足物理限制。

两次正式飞行的分配推力都在 0–8.5 N。由电机状态计算的实际推力如下：

|---|---:|---:|---:|
| Medium seed2 | 0.000959–7.696207 | 47 | 0 |
| Dense seed4 | 0.493977–5.454010 | 3 | 0 |

Ideal 执行和碰撞检测代码未改，继续使用已通过的直接状态与原机体几何碰撞检查。两次 Ideal 飞行也复用已有记录，未重复运行。

预测时域仍为 16 × 0.02 s = 0.32 s。NMPC 按仿真时间以 50 Hz 求解，执行首个控制输入。角速度内环和 Newton 物理步进为 400 Hz。

| NMPC 场景 | 求解次数 | 首次求解 / ms | 全程 P50 / P95 / ms | 运动后 P50 / P95 / ms |
|---|---:|---:|---:|---:|
| Medium seed2 | 754 | 14.646 | 11.391 / 26.637 | 23.762 / 27.987 |
| Dense seed4 | 873 | 9.120 | 10.015 / 25.459 | 23.573 / 26.601 |

全程百分位包含起飞等待期间的真实求解。运动后统计从速度首次超过 0.5 m/s 开始。每次求解同步 CUDA 后计时，构造函数预热单独记录。50 Hz 是仿真调度频率；运动后的墙钟求解耗时仍超过 20 ms。

预热输入现已使用与运行时相同的张量步长。初版首次求解约 3.69 s 的再次编译未在复测出现。两次正式运行的最大求解耗时分别为 35.357 ms 和 32.779 ms。

实验沿用 NVIDIA GeForce RTX 4090。飞行依次运行，设置 `OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=1`。机器上存在其他 GPU 工作，未停止或修改这些任务。因此耗时反映本次实际环境，不是独占 GPU 基准。
