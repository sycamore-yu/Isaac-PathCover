# Newton 执行与验收规则

规划算法保留官方数学定义。Newton 执行器在交接前检查候选轨迹。规划收敛与执行接受分别记录。

## 物理与传感器

仿真使用 Isaac Lab 3.0.0 的 Newton/MJWarp 后端。单架无人机采用 L2F `acmpc_quad` 参数：质量 0.752 kg，重力 9.8066 m/s²，惯量对角元为 `[0.0025, 0.0021, 0.0043]` kg·m²。四个旋翼的位置为 `[±0.075, ±0.1, 0]` m。

每个旋翼的推力为 `8.5 u²` N，电机时间常数为 0.033 s。执行器使用 L2F 的闭式电机状态更新及积分平均推力。它在每个 0.0025 s 物理步更新机体力和力矩。控制器每 0.01 s 更新一次指令。转子指令限制在 `[0, 1]`。

几何控制器移植官方实际启用的 `p/v/a` 重载。该重载根据轨迹切向更新偏航。它不是位置直接赋值，也没有用理想加速度代替电机和刚体积分。

障碍物来自现有 medium 和 dense 的完整体素实体。Newton 使用 762 和 1372 个独立盒体。两个场景的原始体素尺寸均为 0.1 m。机体碰撞尺寸保存在场景资产中，与原 Isaac-L2F 的计算结果一致。

激光雷达使用 440 × 16 射线，垂直视场为 ±15°，量程为 0.1–100 m。传感器位于机体系 `[0, 0, 0.25]` m，方向随实测姿态旋转。这些几何参数来自官方 `lidar.xacro`。本演示将扫描和重新规划统一为 2 Hz；官方传感器发布频率为 5 Hz。

传感器用体素 DDA 计算相同障碍实体的首个命中点。规划器只接收传感器原点和命中点。没有命中的射线不伪造障碍端点。该传感器不包含噪声或运动畸变。

## 地图与时钟

本任务使用已知静态地图。初始化时，场景表面点云通过 `NanoVoxMap.set_occupied` 融合。飞行中，每次扫描通过 `insert_point_cloud` 更新同一稀疏地图。占据集合变化后，下一次规划更新膨胀、搜索栅格和势场。

这项试验验证静态地图中的闭环飞行及点云更新。它没有将未知环境探索作为完成条件。

重新规划在 Newton 物理步之间同步执行。求解时，仿真时间暂停。每次新轨迹从当前实测位置、速度和加速度开始。加速度采用相邻控制帧的速度差。

日志同时保存仿真时间和墙钟耗时。`planning_p50_s` 等字段仅统计规划。`complete_cycle_*` 还包括该次传感器扫描、点云融合、轨迹诊断和执行检查。文件保存与 HTML 渲染不属于这个周期。

2 Hz 是仿真时间中的请求频率。达到该频率的墙钟要求是完整周期不超过 0.5 s。报告单独计数超时，不将暂停的仿真解释为实时飞行。

## 候选轨迹的执行检查

实际验收发现，GCOPTER 可能按相对代价变化停止，却仍违反软约束。medium 的一次计划在 Python 中达到 5.67 m/s。同输入官方 C++ 也产生了 4.97 m/s 的轨迹。两者均超过 3 m/s 的配置值。

因此，执行交接增加了以下检查。它们不修改目标、解析梯度、初始化、时间参数化、L-BFGS 或优化器返回状态。

令 `μ = config.smoothing_eps = 0.01`。执行策略采用该平滑过渡宽度作为软残差容许带。这是新增的执行规则；官方源码没有将 `μ` 定义为可行性保证。

| 检查量 | 接受条件 | 默认对应范围 |
|---|---|---|
| 速度 | `v_max² − v_limit² ≤ μ` | ≤ 3.001666 m/s |
| 机体角速度 | `ω_max² − ω_limit² ≤ μ` | ≤ 3.001666 rad/s |
| 倾角 | `θ_max − θ_limit ≤ μ` | ≤ 0.7954 rad |
| 推力 | `max((T_min−Tm)², (T_max−Tm)²) − Tr² ≤ μ` | 约 1.998750–10.001250 N |
| 原走廊平面 | 最大有符号距离 ≤ 1e-6 m | 只容许微米级几何误差 |

其中 `Tm=(T_lower+T_upper)/2`，`Tr=(T_upper−T_lower)/2`。源优化器的 0.15 m 安全余量仍在目标函数中；执行检查使用原走廊，不把软余量作为硬约束。没有添加源配置中不存在的加速度上限。总代价也不作为执行门槛。

速度和走廊残差通过每段多项式驻点求极值。角速度、倾角和推力每段检查 101 个样本。采样发现超限即可拒绝；通过采样不构成连续时间约束证明。非有限诊断值也导致拒绝。

平坦性检查与源优化器一致，使用零偏航和零偏航角速度。跟踪器则沿速度方向调整偏航。因此，该检查不替代实际机体角速度和旋翼分配的飞行统计。

`planning.json` 保留原 `success`、`status`、`cost`、迭代数及诊断。`execution_check` 保存执行容许带、残差和拒绝原因。`handoff.accepted` 表示本次是否真正替换活动轨迹。被拒绝的候选仍保存在对应 `plans/NNNN/` 中。

## 失败与交接

搜索、几何或优化失败时，执行器继续旧轨迹。求解成功但执行检查不通过时，也继续旧轨迹。第一条轨迹尚未接受时，控制器保持初始悬停参考。旧轨迹结束后，参考保持在其终点。

成功交接使用当前实测状态。记录分别量化新轨迹相对于实测状态的误差，以及新旧参考的跳变。官方 GCOPTER 会裁剪超限初始速度或加速度，因此这两项不能假定恒为零。

执行器没有增加备用求解器或重试参数。每次重新规划沿用同一规划器和持续随机状态。

## 飞行统计

到达要求同时满足：距目标小于 0.2 m，速度小于 0.3 m/s，并持续 0.5 s。高速穿过目标不计为到达。

碰撞统计同时检查 Newton 接触力和机体有向盒与全部障碍盒的相交。几何检查使用 400 Hz 物理样本，并补检最后一次积分后的状态。接触力最大值超过 1e-6 N 时计为碰撞。

报告保留越界、跟踪误差、速度、角速度、倾角、推力分配、转子状态及执行拒绝数。速度、角速度和倾角使用 400 Hz 物理样本。跟踪误差使用 100 Hz 控制样本。规划中的平坦性角速度与实际闭环角速度分别统计。

非有限样本保留在 `flight.npz`。JSON 中无法表示的统计值写为 `null`，并记录无效样本和未完成碰撞检查的数量。此类试验不计为成功。
