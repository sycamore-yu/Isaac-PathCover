# 映射与全局搜索验证

本模块的 18 项针对性测试已通过。官方 C++ 对照覆盖 NanoVoxMap 占据融合、障碍膨胀、三维 Jump Point Search（JPS）和 Distance Map Planner（DMP）。medium、dense 的 JPS 路径与官方逐点一致。两图 DMP 目标值的绝对误差均为 `2.2737367544323206e-13`。

本文记录 2026-11-14 已完成的实验。轨迹优化和 Newton 飞行结果由各自报告说明。本文的搜索路径合法性检查不替代连续轨迹碰撞检查。

## 2. NanoVoxMap：单元占据与射线融合

### 2.1 保留的数值语义

地图以世界原点为体素格原点。点坐标按 `floor(p / resolution)` 转为整数体素坐标。默认分辨率为 `0.05 m`，存储采用稀疏 `8×8×8` 块。

每个体素存储 `int8` 对数几率。量化定义为：

\[
L(p)=\operatorname{round}_{\text{away from zero}}
\left(20\log\frac{p}{1-p}\right).
\]

每次更新后，将数值夹到配置的最小值和最大值。体素占据条件为 `L > 0`。没有观测的体素为 `0`。

| 配置 | `p_hit` | `p_miss` | 命中增量 | 未命中增量 | 最小值 / 最大值 |
|---|---:|---:|---:|---:|---:|
| 对照配置 A | 0.7 | 0.4 | 17 | −8 | −40 / 70 |
| 官方默认、对照配置 B | 0.9 | 0.1 | 44 | −44 | −40 / 70 |

两组配置均使用 `p_min=0.1192`、`p_max=0.971`。对照夹具采用 `0.2 m` 分辨率，以便覆盖正负坐标和体素边界。

射线使用 Amanatides–Woo 体素遍历。遍历从起始体素中心计算交点参数。参数相等时，依次优先选择 x、y、z 轴。射线路径不包含终点体素；终点在第二阶段更新。

一次点云融合先处理全部射线的未命中更新，再处理全部终点更新。`apply_hits=False` 时，第二阶段也执行未命中更新。Python 在每个单调更新阶段合并重复体素次数，再执行饱和运算。由于同一阶段的增量同号，该合并保留串行更新结果。

已知静态点云通过 `set_occupied(points)` 初始化。该接口对应官方 `setOccupied`，直接设置最大对数几率。初始化不假定传感器原点。后续真实扫描使用 `insert_point_cloud(origin, endpoints)`。

### 2.2 同输入 C++ 对照

每组配置使用相同起始状态：

```text
setOccupied: [-0.5, 0.3, 0.5]
setFree:     [-0.7, 0.3, 0.5]
origin:      [ 0.1, 0.1, 0.1]
```

点云包含以下 7 个终点：

```text
[ 1.10,  1.10,  1.10]
[-1.10,  0.10,  0.50]
[ 0.10,  0.10,  0.10]
[ 1.10,  0.10,  0.10]
[ 1.10,  0.10,  0.10]
[ 0.90,  0.90,  0.90]
[-0.01, -0.01, -0.01]
```

输入覆盖重复终点、零长度射线、轴向射线、对角线平局和负坐标。连续执行 4 次融合，`apply_hits` 依次为 `True, True, False, True`。

测试在每次融合后比较官方完整状态指纹和占据指纹。完整状态指纹包含每个非零体素的整数坐标与 `int8` 对数几率。测试还按坐标排序，逐点比较全部占据体素中心，绝对容差为 `2e-15 m`。

**结果：8 组完整状态指纹和占据指纹均一致。** 两组配置各阶段的占据体素数量分别为 `[6, 6, 6, 6]` 和 `[7, 7, 4, 7]。[官方输出](../../tests/fixtures/mapping_search.json)

该 C++ 夹具通过官方 64 位指纹比较完整对数几率状态，没有导出全部自由体素的逐单元数值表。占据集合另做逐坐标比较。性能优化前后的 Python 对照则直接比较完整整数坐标及对数几率数组。

另外两项测试验证地图变更行为。重复设置已占据点不改变版本。连续清除射线可以清空原占据点。一次扫描内部若先清除、再恢复同一体素，且最终占据集合不变，则 `version` 不增加。该规则使几何缓存只因占据集合变化而失效。

## 3. 障碍膨胀

默认膨胀分辨率为 `0.1 m`，水平半径为 `0.45 m`，竖直半径为 `0.25 m`。默认形状是椭球，输出为 26 邻域定义的单层表面。内部同时保留实心体素集合。

输入沿用官方 float32 点云量化规则。膨胀核来自整数格点上的椭球或盒体条件。实现按官方核的 x 轴连续段执行最大值滤波及平移合并。该优化没有改变核中的整数偏移集合。

对照输入为 4 个点：`[0.05,0.05,1.05]`、`[0.35,0.05,1.05]`、`[-0.15,0.15,0.95]`、`[0.05,0.05,-0.05]`。最后一个点验证官方默认输入高度过滤。对照结果如下。

| 配置 | 核体素数 | 实心体素数 | 输出点数 | float32 坐标最大绝对误差 |
|---|---:|---:|---:|---:|
| 椭球、实心输出 | 225 | 436 | 436 | 0 |
| 椭球、表面输出 | 225 | 436 | 334 | 0 |
| 盒体、实心输出 | 847 | 1,385 | 1,385 | 0 |
| 椭球、竖直半径为 0 | 69 | 165 | 165 | 0 |

测试逐元素比较排序后的 float32 输出点云，并检查核大小和实心体素数。另有两项测试检查非增量模式删除障碍，以及增量模式与输入点云并集膨胀的一致性。[测试实现](../../tests/test_mapping.py)

## 4. JPS/DMP：路径、势场与目标值

### 4.1 保留的搜索定义

搜索栅格默认分辨率为 `0.25 m`。它与 NanoVoxMap 的 `0.05 m`、膨胀模块的 `0.1 m` 分辨率分别保留。膨胀点云按官方规则重新栅格化，形成搜索输入。

JPS 使用官方三维 26 邻居图。自然邻居、强制邻居和跳跃递归顺序均来自源码。测试逐元素检查全部 27 组方向表，包括初始零方向。图允许官方定义的对角步；实现没有附加改变图结构的转角约束。

JPS 的自由体素条件为值等于 `0`。未知值 `-1` 阻止跳跃。强制邻居的障碍判定仍要求值大于 `0`。地图边界外不能通行，也不计作强制邻居障碍。

实际 PathCover 配置令 `JpsHeuristicWeight=VoxelResolution`，因此真实场景使用 `0.25`。小场景同时验证 `0.25` 和 `1.0` 两种权重。优化没有提高该权重来减少搜索量。

DMP 的默认参数为：

| 参数 | 数值 |
|---|---:|
| 势场半径 | `(1,1,1) m` |
| 搜索区域半径 | `(2,2,2) m` |
| 启发式权重 | 0 |
| 势场代价权重 | 0.1 |
| 势场指数 | 1 |
| 地图范围参数 | `(0,0,0)`，使用全图 |

对障碍附近的整数偏移 `(i,j,k)`，势场核保留官方截断量化：

\[
\phi(i,j,k)=\operatorname{int}\left[
100\left(\left(1-\frac{\sqrt{i^2+j^2}}{r_n}\right)
\left(1-\frac{|k|}{h_n}\right)\right)^p\right],
\]

其中 `r_n=ceil(radius_xy/resolution)`，`h_n=ceil(radius_z/resolution)`，偏移限定在核的支撑范围内。重叠核取最大值。Python 使用最大值加法膨胀运算实现同一整数势场。路径引导区域保留沿 JPS 路径扩展的圆柱形整数邻域。

DMP 在启发式权重为 0 时搜索原目标：

\[
g(v_0)=\phi(v_0),\qquad
J=\phi(v_0)+\sum_{i=1}^{N}
\left(\|v_i-v_{i-1}\|_2+0.1\phi(v_i)\right).
\]

这里的 `v_i` 是整数栅格坐标。初始点势场没有乘 `0.1`，与官方实现一致。JPS 代价也以栅格步长计量，不直接以米计量。

正式数据流使用 JPS 原始路径引导 DMP，再将 DMP 原始路径交给走廊生成。精确世界坐标起终点保留在结果中。路径简化接口没有替代这条调用链。

### 4.2 小场景对照

夹具使用 `20×18×10` 栅格，分辨率为 `0.25 m`。地图包含带孔墙和独立障碍块。两种 JPS 权重的官方路径代价均为 `20.384776310850242`，DMP 代价均为 `48.27758621965183`。

测试将同一条官方 JPS 原始路径传给 Python DMP，以隔离 JPS 等代价路径选择对搜索区域的影响。测试检查：

- DMP 势场的全部 3,600 个体素逐元素相等。
- JPS/DMP 目标值满足 `1e-12` 绝对误差容差。
- 每个 DMP 路径体素均可通行，相邻体素差不超过 1。
- 除起始点外，路径体素均属于规定的搜索区域。
- 独立按路径边长和势场值重算 DMP 目标值。
- 搜索输出保留指定起终点。
- 占据墙和未知墙封闭地图时，JPS 正常报告搜索失败。

## 6. 性能优化与测量边界

### 6.1 五次配对实验

以下结果比较 Python 优化前后实现，不是 Python 与 C++ 的比较。每个场景在同一进程内执行 5 次配对试验，交替改变前后版本的执行顺序。每轮创建新的地图和膨胀对象，使用相同输入。

此历史微基准使用固定 `180×16` 条候选射线、`20 m` 最大距离。medium 有 1,496 条命中射线，dense 有 849 条。表中的射线融合仅计地图融合，不包含传感器观测生成。

**该输入不同于最终飞行传感器。** 最终配置采用 `440×16`、`0.1–100 m`、机体偏移 `[0,0,0.25] m`，射线随机体姿态旋转，并按演示重规划节奏以 `2 Hz` 更新。下面的数据不能作为该飞行配置的扫描耗时。

| 场景与阶段 | 优化前 p50 / p95 | 优化后 p50 / p95 | p50 加速比 |
|---|---:|---:|---:|
| medium，静态点云插入 | 170.97 / 193.63 ms | 36.26 / 51.02 ms | 4.72× |
| medium，射线融合 | 564.09 / 594.61 ms | 153.19 / 187.82 ms | 3.68× |
| medium，障碍膨胀 | 350.82 / 401.77 ms | 222.18 / 253.41 ms | 1.58× |
| dense，静态点云插入 | 351.59 / 357.86 ms | 65.02 / 66.79 ms | 5.41× |
| dense，射线融合 | 173.92 / 181.08 ms | 54.48 / 60.10 ms | 3.19× |
| dense，障碍膨胀 | 682.38 / 698.12 ms | 309.14 / 335.96 ms | 2.21× |

优化包括稀疏体素块池、整数索引排序归并、矢量化饱和更新，以及按官方 x 轴连续段执行膨胀。两图优化前后的完整对数几率数组和膨胀点云均逐元素一致。全部 5 次原始时间及输入哈希保存在 [性能记录](../../tests/fixtures/mapping_search_performance.json)。

5 次样本的 p95 是样本分位数估计，不是 95% 置信界限。实验没有记录独占 CPU、亲和性、温度或频率控制，因此结果反映本机观测，不承诺其他主机或负载下的时延。

### 6.2 搜索优化的探索计时

搜索优化包括 JPS 跳跃结果记忆化、线性索引、地图相关强制邻居缓存，以及 DMP 整数势场和圆柱搜索区域的形态学计算。全局势场在同一地图对象上缓存。

历史记录另含优化前后各 3 次顺序搜索测量。medium 的 JPS 中位时间从约 `936 ms` 降为 `508 ms`，DMP 从约 `756 ms` 降为 `347 ms`。dense 的对应时间为 `554→323 ms` 和 `734→195 ms`。

这组测量未采用上述 5 次交替配对设计，还包含对象和缓存准备差异。因此，它只作为热点优化的探索证据。两图的势场、搜索区域、路径和目标值在优化前后均一致。扩展节点数也保持一致：medium 的 JPS/DMP 为 `19,052 / 13,385`，dense 为 `13,405 / 7,610`。

### 6.3 官方 C++ 与 Python 时间

小场景使用 10 次测量。JPS 计时范围为规划调用；DMP 两侧均排除势场构建，包含路径区域构建和路径搜索。

| 小场景阶段 | C++ p50 / p95 | Python p50 / p95 |
|---|---:|---:|
| JPS，权重 0.25 | 1.69 / 2.21 ms | 23.07 / 33.78 ms |
| DMP | 4.26 / 5.96 ms | 64.00 / 90.51 ms |

| medium | 33.55 / 426.28 ms | 50.25 / 63.87 ms | 26.20 / 290.48 ms |

不同实现的对象准备和内部数据结构仍有差异。真实场景单次时间没有稳定分位数意义。Python 搜索明显慢于 C++，不能将本次优化描述为已经达到原实现速度。这些结果也不包含走廊生成、轨迹优化或 Newton 仿真时间。
