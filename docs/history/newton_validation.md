# Newton 飞行验证

原交接基线的无碰撞到达结果为 medium 2/5、dense 5/5。新增执行检查后，结果为 medium 5/5、dense 5/5。两组各测试 10 次，使用种子 0–4。所有失败、碰撞和被拒候选均保留。

完整数据、原始报告副本、源文件清单及原始文件 SHA-256 保存在 [newton_validation.json](../data/newton_validation.json)。下表由该数据生成。

## 1. 实验条件与判断口径

Newton/MJWarp 以 400 Hz 仿真，控制器以 100 Hz 更新，重新规划周期为 0.5 s 仿真时间。规划期间暂停推进物理时间；优化结束后，才从当前仿真时刻交接轨迹。这是同步仿真实验，不能说明系统满足墙钟实时执行。

主机使用共享 NVIDIA GeForce RTX 4090，测量期间还有其他实验运行。下文的墙钟耗时含资源争用，不是独占 GPU 基准。Python 3.12.14、PyTorch 2.11.0+cu130、NumPy 2.5.1、Newton 1.6.1；Isaac Lab 发布版本为 3.0.0，安装的核心分发版本为 28.0.0。运行元数据保留在各原始报告中。

这组 5 种子验收使用既有 Isaac Lab 3.0 依赖环境，运行时核心代码已经冻结。后续干净环境的独立安装检查不计入这两组成功率。

独立最小环境随后也完成了两图种子 0 飞行。两图均无碰撞到达；状态、参考、电机状态及物理记录与本组同一种子逐元素一致。该结果单独保存在 [installed_demo_validation.json](../data/installed_demo_validation.json)。

medium 使用已有 100 个障碍场景。dense 使用已有重建的 180 个障碍场景；其重建属性、原始文件哈希及体素资产哈希均保留在数据中。测试开始时，规划器已融合完整静态场景点云；后续使用机载几何 LiDAR 更新地图。这验证已知静态地图中的更新与重新规划，不等同于从空地图探索。

LiDAR 使用 440×16 条射线，水平视野 360°、垂直视野 ±15°，量程 0.1–100 m，机体外参为 [0, 0, 0.25] m，方向随机体姿态旋转。本次扫描与重规划同步，为 2 Hz；官方传感器配置为 5 Hz。几何射线与 Newton 碰撞采用相同体素实体。

到达要求距离目标小于 0.2 m、速度小于 0.3 m/s，并连续保持 0.5 s。“无碰撞到达”还要求整段记录没有碰撞。碰撞由 Newton 接触力与机体盒对障碍盒的几何检查共同统计；几何检查覆盖 400 Hz 子步和终止末帧。有限状态、越界和碰撞检查完整性分别保留。

两组使用相同规划、轨迹、动力学、跟踪器和传感器实现。源清单的变化仅涉及执行交接、演示编排和指标采样；完整差异见数据中的 source_comparison。原交接基线接受 GCOPTER 返回成功的轨迹。新增策略在交接前检查轨迹，拒绝超限候选并保留旧轨迹。它没有修改 GCOPTER 的目标、梯度、停止条件或返回成功状态。

新增策略允许原惩罚残差在平滑宽度 0.01 内波动：速度平方、角速度平方、倾角及居中推力平方按原残差单位检查；原走廊残差容许 1e-6 m。0.01 是本工程采用的执行容许带，不是官方可行性保证。速度和走廊使用多项式驻点检查；姿态、角速度及推力仍为每段 101 点采样。采样发现超限即可拒绝，未发现超限不构成连续时间证明。

## 7. 数据边界与复核

400 Hz 运动和碰撞指标仍是离散物理步状态，不是对步间连续运动的形式化证明。姿态约束的 101 点/段检查和电机推力的 100 Hz 统计也有各自采样边界。几何地图静态、初始地图已知、样本为两场景各 5 种子；本实验未验证动态障碍、未知地图探索或异步墙钟规划。

JSON 包含每次原始 result.json 的完整内容，以及 result.json、planning.json、mapping.json、flight.npz、场景 summary.json 和 source_hashes.json 的 SHA-256。源清单保存运行时全部 Python 文件的哈希，不以事后工作区文件代替运行版本。两组数据目录分别为 results/validation_final_20261114 和 results/validation_execution_20261114。

失败和拒绝明细保存在各 episode 的 planning 字段；分阶段耗时保存在 phase_timings_s。图示、完整轨迹与走廊仍位于各 seed 结果目录。版本化 JSON 已包含本页所需的原始报告和派生数据，阅读本页不依赖被忽略的实验目录。
